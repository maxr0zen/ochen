# Подключение AI-композиции

Подготовлены Gemini и Groq. Ключа в проекте нет; живые запросы к этим API и качество их компоновки ещё не проверялись. Тесты используют явно подменённые ответы провайдеров, а не демонстрируются как ответы настоящей модели.

## Первый запуск

1. В каталоге проекта выполните `npm ci`, затем `npm run ai:setup`. Последняя команда создаёт `.env.local` с отдельным случайным кодом подключения. Существующий файл не перезаписывается.
2. Откройте `.env.local`. Для Gemini укажите `GEMINI_API_KEY=...`, оставив `AI_PROVIDER=gemini`. Для Groq укажите `AI_PROVIDER=groq` и `GROQ_API_KEY=...`. Ключ не нужно присылать в чат или вставлять в плагин.
3. Запустите `npm run ai` и оставьте терминал работающим. Если настройки изменены после запуска, перезапустите сервер.
4. Перезапустите development-плагин в Figma, откройте «AI-композиция · Gemini / Groq». В поле кода подключения вставьте **значение AI_CONNECTION_TOKEN**, а не API-ключ. Нажмите «Проверить подключение AI».
5. Введите метафору либо названия компонентов, выберите формат, детализацию, состояния и палитру. Нажмите «Предложить AI-композицию».
6. Рассмотрите предпросмотр. Можно написать пожелание в «Что изменить в расположении?» и нажать «Улучшить AI-план». «Добавить AI-сцену в Figma» создаёт редактируемые копии исходных предметов. До этого холст не меняется.

Владелец рабочего проекта уже имеет созданный `.env.local`; ключи в нём оставлены пустыми. Сервер автоматически не оставлен работающим: запускайте его командой выше после настройки.

## Провайдеры

- **Gemini**: по умолчанию `gemini-3.1-flash-lite`, модель можно изменить в `GEMINI_MODEL`. Получение ключа: https://aistudio.google.com/api-keys . Доступ зависит от региона и аккаунта: https://aistudio.google.com/docs/available-regions .
- **Groq**: по умолчанию `openai/gpt-oss-120b`, модель задаётся в `GROQ_MODEL`. Получение ключа: https://console.groq.com/docs/quickstart . Этот адаптер использует текстовые описания, размеры и предыдущий JSON-план.

Доступность бесплатной квоты и конкретной модели определяется аккаунтом провайдера. Ключ платного аккаунта может расходовать его средства. Автоматическое переключение на другие или платные модели не выполняется.

## Что отправляется

Всегда отправляются запрос, названия, теги, размеры разрешённых предметов, формат, ограничения и начальный локальный план, если он найден. Исходные SVG-контуры, Figma nodeId и API-ключ в тексте запроса отсутствуют.

Для Gemini можно отдельно включить «Отправлять миниатюры предметов и предпросмотр». По умолчанию опция выключена. При включении передаётся PNG-лист с подписями объектов; при уточнении добавляется PNG текущего предпросмотра. Растеризация используется только для анализа моделью: состав и экспорт итоговой сцены остаются векторными. Для Groq отправка изображений отключена.

Условия обработки данных провайдерами нужно учитывать до отправки закрытых материалов. Например, бесплатный тариф Gemini предусматривает использование данных для улучшения продуктов: https://aistudio.google.com/docs/pricing .

## Архитектура и ограничения

Панель Figma → локальный сервер `http://localhost:4174` → выбранный API → JSON-план → независимая проверка в сервере и панели → предпросмотр → повторная проверка в Plugin API → векторная сцена.

- `server/ai-server.ts` хранит API-ключ только в серверном процессе, связывается с официальными API и не возвращает ключ в панель. Сервер слушает только loopback `127.0.0.1`, для запросов нужен отдельный код подключения.
- `src/ai-plan.ts` разрешает модели только существующие assetId, координаты, поворот и порядок слоёв. Проверяет S/L, состояния, количество, крупные перекрытия и сохраняет общий масштаб всей композиции.
- `src/scene-svg.ts` строит векторный предпросмотр из исходных миниатюр. Сам итог в Figma создаётся клонированием библиотечных узлов, как и в локальном режиме.
- Код подключения сохраняется в личном `figma.clientStorage`, а не в общем Figma-документе. `.env.local` исключён из git и архива доставки; `.env.example` содержит только шаблон.
- В manifest добавлен только локальный development-домен `http://localhost:4174`. Прямого доступа плагина к Google/Groq нет. Для опубликованного плагина потребуется отдельное серверное размещение и настройка домена.
- Лимиты API, неверный ключ, недоступная модель, ошибочный JSON и недопустимая композиция показываются как ошибки. Текущая сцена не подменяется локальной с ложной пометкой AI. Обычная локальная сборка доступна отдельно.

## Проверки без ключа

`npm run check` проверяет типы, тесты и сборку. Тесты AI-плана запрещают новые объекты, деформации, неверные количества и скрытые предметы. HTTP-тесты поднимают настоящий локальный сервер, но подменяют только upstream API: проверяют авторизацию, пустой ключ, валидный и неверный ответ.

`npm run test:ui` проверяет получение плана, предпросмотр, явное применение, изображения по выбору и уточнение. Это проверка интеграционного контракта, не оценка художественного качества реальной модели.

После добавления ключа нужен пробный запрос к настоящему API и сравнение его результата с локальной компоновкой на одинаковых запросах.

`npm run ai:check` проверяет локальный сервер и авторизацию с настройками из `.env.local`, создаёт `output/ai-connection-check.json`. Внешний API эта команда намеренно не вызывает, даже если ключ уже указан. Она не проверяет правильность API-ключа.
